🗑️ Esercizio 4: Cancellazione senza Controlli

Cancellare servizi già erogati – Un problema di integrità
🎯 L'Obiettivo dell'Attaccante
Immagina questo scenario: ho prenotato e già usufruito di un servizio (cena al ristorante, notte in hotel). Lo stato è completed.

Cosa voglio fare? Cancellare la prenotazione dopo aver usato il servizio, evitando il pagamento o ottenendo un rimborso fraudolento.
🤔 La Vulnerabilità
Nel file cancel_booking.php:
// ❌ VULNERABILE $stmt = $conn->prepare( "UPDATE bookings SET status = 'cancelled' WHERE id = ?" ); // Non verifica: // - Se status='completed' (già erogato!) // - Se la data è nel passato // - Se è stato pagato
📝 Passaggi dell'Attacco
Step 1: Crea una prenotazione normale

Step 2: Simula il completamento del servizio. Accedi al database:
mysql -h localhost -P 3304 -u root -prootpassword booking_system UPDATE bookings SET status = 'completed' WHERE id = 1;

Step 3: Torna all'applicazione → Dashboard

Step 4: Clicca "Cancella" sulla prenotazione completata

Risultato: La prenotazione viene cancellata anche se il servizio è stato erogato!
🛡️ Lezione per il Difensore
1. Impedire cancellazione se status = 'completed'
2. Impedire cancellazione meno di 24h prima dell'evento
3. Se pagato, gestire prima il rimborso (con approvazione manuale)
4. Logging di tutte le operazioni critiche per audit
