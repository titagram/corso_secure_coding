📝 Esercizio 3: Modifica Prenotazioni Confermate

Bypassare i controlli di stato – Modificare l'immodificabile
🎯 L'Obiettivo dell'Attaccante
Una prenotazione confermata o completata non dovrebbe essere modificabile. Ma cosa succede se il sistema non controlla lo stato?

Scenario: Ho una prenotazione per 2 persone a €100, già confermata. Voglio cambiarla a 10 persone mantenendo il prezzo originale, oppure modificare il prezzo dopo che è stata approvata.
🤔 La Vulnerabilità
Nel file modify_booking.php:
// ❌ VULNERABILE $stmt = $conn->prepare( "UPDATE bookings SET ... WHERE id = ?" ); // Non verifica: // - Se status='confirmed' o 'completed' // - Se la data è nel passato // - Se c'è disponibilità per le modifiche
📝 Passaggi dell'Attacco
Step 1: Crea una prenotazione e falla confermare (o confermala tu se hai accesso admin)

Step 2: Vai su Dashboard → Modifica Prenotazione

Step 3: Modifica uno o più campi:
  • 📅 Data: anche una data nel passato!
  • ⏰ Ora: qualsiasi orario
  • 👥 Ospiti: superiore alla capacità massima
  • 💰 Prezzo: €0.01 (sì, anche dopo la conferma!)

Step 4: Salva le modifiche – Verranno applicate senza controlli!
🛡️ Lezione per il Difensore
Implementare una macchina a stati: pending → confirmed → completed → cancelled. Ogni transizione ha regole specifiche. Una prenotazione confirmed può solo essere cancellata (con penali), mai modificata. Mai permettere modifiche su date passate.
