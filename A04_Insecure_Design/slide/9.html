📊 Esercizio 5: Bypass Controlli di Capacità

Creare overbooking bypassando i vincoli – Quando 4 posti diventano 100
🎯 L'Obiettivo dell'Attaccante
Un servizio ha max_capacity = 4 (es. "Tavolo Romantico"). Vogliamo prenotare per 10 persone, oppure creare multiple prenotazioni per lo stesso slot causando overbooking.

Perché è possibile? La validazione è solo lato client (attributo HTML max), ma il server non verifica nulla.
🤔 La Vulnerabilità
Nel file create_booking.php:
// ❌ VULNERABILE $stmt = $conn->prepare( "INSERT INTO bookings (...) VALUES (...)" ); // Non verifica: // - Se guests > max_capacity // - Se esistono già prenotazioni per // quella data/ora // - Se il servizio è attivo
📝 Passaggi dell'Attacco
Metodo 1 – DevTools:
Apri F12 → Elements → Trova l'input number_of_guests → Rimuovi l'attributo max="4" → Inserisci 100 → Invia

Metodo 2 – Burp Suite:
Intercetta la richiesta POST e modifica:
number_of_guests=4 → number_of_guests=100

Metodo 3 – Race Condition:
Invia 10 prenotazioni simultanee per lo stesso slot. Senza lock/transazioni, tutte verranno accettate!
🛡️ Lezione per il Difensore
1. Validazione server-side: if ($guests > $service['max_capacity']) die();
2. Query di controllo disponibilità prima dell'inserimento
3. Usare transazioni DB con SELECT FOR UPDATE per evitare race conditions
4. Mai fidarsi degli attributi HTML per la validazione
