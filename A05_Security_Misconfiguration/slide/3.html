📄 Esercizio 1: File di Configurazione Esposti

Quando i segreti sono a portata di URL
🎯 L'Obiettivo dell'Attaccante
Molti sviluppatori lasciano file di configurazione nella document root del web server. Questi file contengono:

• Credenziali database (user, password, host)
• API Keys e Secret Keys
• Password admin hardcoded
• Chiavi di cifratura
🤔 Perché Funziona?
Il file config.php dovrebbe essere eseguito da PHP, non scaricato. Ma se:

• Il file ha estensione .txt, .bak, .old
• PHP non è configurato correttamente
• Il file è in una directory senza handler PHP

...il contenuto viene servito in chiaro!
📝 L'Attacco
Step 1: Accedi direttamente al file di configurazione:
http://localhost:8005/config.php http://localhost:8005/environment.txt

Step 2: Estrai le credenziali trovate:
define('DB_HOST', 'db'); define('DB_USER', 'root'); define('DB_PASS', 'rootpassword'); define('ADMIN_PASSWORD', 'admin123'); define('API_KEY', 'sk_live_1234567890abcdefghijklmnop'); define('SECRET_KEY', 'my_super_secret_key_12345');
🛡️ Lezione per il Difensore
1. Sposta i file di config fuori dalla document root
2. Usa variabili d'ambiente invece di file
3. Blocca l'accesso con .htaccess o configurazione Apache
