🏷️ Esercizio 6: Server Signature e Headers Mancanti

Fingerprinting del server e mancanza di protezioni
🔍 Server Signature Esposta
Con ServerTokens Full, Apache rivela:

• Versione esatta di Apache
• Sistema operativo
• Moduli installati
• Versione di PHP
Server: Apache/2.4.54 (Debian) X-Powered-By: PHP/8.1.12

Rischio: L'attaccante cerca exploit specifici per quella versione!
🛡️ Headers di Sicurezza Mancanti
Headers che dovrebbero essere presenti:
X-Content-Type-Options: nosniff X-Frame-Options: DENY X-XSS-Protection: 1; mode=block Strict-Transport-Security: max-age=... Content-Security-Policy: default-src 'self'

Senza questi: Clickjacking, XSS, MIME sniffing sono possibili.
📝 L'Attacco
Step 1: Controlla gli header HTTP con curl:
curl -I http://localhost:8005

Step 2: Genera una pagina di errore 404 per vedere la signature nel footer:
curl http://localhost:8005/pagina_inesistente.php # Output: "Apache/2.4.54 (Debian) Server at localhost Port 8005"

Step 3: Cerca exploit per la versione identificata su exploit-db.com
🛡️ Lezione per il Difensore
1. ServerTokens Prod e ServerSignature Off
2. Rimuovi X-Powered-By con expose_php = Off
3. Aggiungi tutti i security headers con mod_headers
