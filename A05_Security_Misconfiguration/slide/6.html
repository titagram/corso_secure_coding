💾 Esercizio 4: File di Backup Esposti

Il dump del database a portata di click
🎯 L'Obiettivo dell'Attaccante
I backup del database sono oro puro per un attaccante:

• Struttura completa del database
• Password hash da craccare offline
• Dati personali di tutti gli utenti
• Dati storici che potrebbero non essere più nel DB attivo
• Relazioni tra tabelle (utile per altri attacchi)
🤔 Perché Succede?
Gli amministratori spesso:

• Creano backup nella document root
• Usano nomi prevedibili (backup.sql)
• Dimenticano di eliminarli dopo il restore
• Non configurano blocchi per estensioni .sql, .bak
📝 L'Attacco
Step 1: Cerca file di backup con nomi comuni:
http://localhost:8005/backup.sql http://localhost:8005/backup_2024-11-20.sql.bak http://localhost:8005/backups/ ← Directory listing!

Step 2: Scarica e analizza il dump:
-- Dal file backup.sql INSERT INTO users VALUES (1, 'admin', '$2y$10$hash...', 'admin@example.com', 'admin'); INSERT INTO users VALUES (2, 'mario.rossi', '$2y$10$hash...', 'mario@example.com', 'user');

Step 3: Cracka gli hash offline con hashcat o John the Ripper
🛡️ Lezione per il Difensore
1. Mai salvare backup nella document root
2. Cifrare i backup con openssl enc -aes-256-cbc
3. Bloccare estensioni .sql, .bak, .old nel web server
