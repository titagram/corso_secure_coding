🐳 Preparazione dell'Ambiente

Il campo di battaglia: un e-commerce vulnerabile
🚀 Avvio del Target
L'applicazione è containerizzata con Docker. Un singolo comando avvia l'intero ambiente vulnerabile:
$ docker-compose up -d
Perché Docker? Isola l'ambiente vulnerabile dal sistema host, permettendo test sicuri e riproducibili.
🌐 Servizi Esposti
Una volta avviato, il target espone:
🌐 Web App: http://localhost:8002 🗄️ MySQL: localhost:3302
Nota: Porte non standard (8002, 3302) per evitare conflitti con servizi locali.
🔑 Credenziali Database (che NON dovremmo conoscere...)
Nel mondo reale, queste credenziali sarebbero segrete. Ma le vulnerabilità crittografiche che esploreremo ci permetteranno di ottenerle:
Host: db / localhost:3302 Database: ecommerce_db Username: root Password: rootpassword ← Password debole!
⚠️ Prima vulnerabilità identificata: Password root predittabile. Un attaccante con accesso alla rete potrebbe indovinarla con un attacco brute-force.
