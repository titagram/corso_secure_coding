🔓 Lab Parte 4: Verifica Compromissione Casella

Se l'attaccante conosce i contenuti, qualcuno ha accesso
🚨 Il Fatto
L'attaccante conosceva i dettagli esatti della conversazione (ordine, importi, nomi). Questo è impossibile senza accesso alle email.

Possibili scenari:
1. Casella del cliente compromessa (nuovokolor.com)
2. Casella del fornitore compromessa (monaco.mc)
3. Regola di inoltro malevola attiva
4. App OAuth con accesso alla posta
🔍 Microsoft 365 – Verifiche
1. Accessi recenti:
Azure AD → Sign-in logs Cerca: login da Paesi anomali login con IP sospetti login falliti ripetuti

2. Regole di inoltro:
Exchange Admin → Mail flow → Rules Outlook → File → Rules → Manage Rules Cerca: Forward to external address
🔍 Google Workspace – Verifiche
1. Attività dispositivi:
myaccount.google.com → Sicurezza → I tuoi dispositivi → Attività di sicurezza recenti

2. App con accesso:
myaccount.google.com → Sicurezza → App di terze parti con accesso Cerca: App sconosciute con "Leggi la posta"
⚠️ Indizio Cruciale del Caso
Lo stesso tipo di attacco è avvenuto a Febbraio su un'altra casella dello stesso cliente. → Pattern identico = compromissione sistemica o password riutilizzate su più account.
